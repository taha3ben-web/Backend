# ADR-0005: قفل مطابقة موزّع للتزامن

- **الحالة:** مقبول (Accepted)
- **التاريخ:** 2026-07-17

## السياق

عند تشغيل عدّة نسخ من الخادم خلف Load Balancer، قد تحاول عمليات متوازية إسناد
نفس السائق لرحلتين، ممّا يسبّب تعارض إسناد (double-dispatch).

## القرار

قفل موزّع عبر Redis لحجز السائق أثناء المطابقة:

- مفتاح حجز لكل سائق `driverOfferKey(driverUserId)` → `offer:driver:<id>`.
- تصفية المرشّحين غير المحجوزين `filterUnreserved(candidateIds, reserved)` (تحافظ على الترتيب).
- البحث الجغرافي عبر Redis GEO.

## البدائل المرفوضة

- قفل قاعدة بيانات (SELECT FOR UPDATE): يزيد الضغط والتأخّر على مسار حرج زمنيًّا.

## التبعات

- منطق القفل نقيّ وقابل للاختبار (اختبارات تزامن في المرحلة 76).
- يعتمد على توفّر Redis (راجع Runbook انقطاع Redis).

## المراجع

`src/modules/matching/matching-lock.util.ts` واختباراته؛ وحدة `src/modules/matching/`.
