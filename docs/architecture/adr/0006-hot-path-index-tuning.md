# ADR-0006: ضبط فهارس المسارات الساخنة وسياسة المايجريشن الإضافية

- **الحالة:** مقبول (Accepted)
- **التاريخ:** 2026-07-17

## السياق

مع نموّ جداول الأحداث (`PaymentEvent`، `OutboxEvent`)، أصبحت بعض استعلامات الرصد
والصيانة تمسح نطاقات زمنية دون فهرس داعم.

## القرار

إضافة فهارس مركّبة دقيقة تدعم الاستعلامات الفعلية فقط، مع تجنّب التكرار:

- `PaymentEvent(createdAt)` و`PaymentEvent(status, createdAt)`.
- `OutboxEvent(status, deliveredAt)` و`OutboxEvent(status, updatedAt)`.

وسياسة عامّة: مايجريشن الفهارس **إضافية غير كاسرة**؛ وعلى الجداول الضخمة في الإنتاج
يُفضّل `CREATE INDEX CONCURRENTLY`.

## البدائل المرفوضة

- فهرسة كل عمود احتياطيًّا: يزيد كلفة الكتابة على جداول ساخنة دون مبرّر.
- فهارس مركّبة تتداخل مع بادئة فهرس قائم (مثل `OutboxEvent(name)`): مرفوضة للتكرار.

## التبعات

- أي استعلام ساخن جديد يُراجع مقابل الفهارس القائمة قبل إضافة فهرس جديد.
