# المرحلة هـ — الوثائق القانونية (الشرط 11)

## 1. ما كان موجودًا فعلًا ولم يُعَد بناؤه

فُحصت وحدة `src/modules/legal/` بالكامل قبل أي تعديل. **النظام مكتمل تقريبًا**، ويحقق الشرط 11 من حيث الجوهر:

| المطلوب في الشرط 11 | الحالة قبل هذه المرحلة |
| --- | --- |
| النص لا يُكتب داخل التطبيق | محقّق — `body` و`title` في جدول `LegalDocument` |
| المحتوى يأتي من الخادم | محقّق — `GET /api/public/legal` (عام، بلا مصادقة) |
| اللوحة تدير الشروط والخصوصية | محقّق — `POST/PATCH/GET /api/legal-documents` بصلاحية `settings.manage` |
| عدم حذف شاشة Legal | لم يُحذف شيء |

وفيه أكثر من المطلوب: سير عمل مسودة/نشر (`status`, `publishedVersion`, `publishedTitle`, `publishedBody`)، وجدول إصدارات `LegalDocumentVersion`، وموافقات موثّقة `UserConsent` مع `ipAddress` و`userAgent`، وجمهور مستهدف `LegalAudience` (ALL / PASSENGER / DRIVER)، وأنواع خمسة `PRIVACY_POLICY`, `TERMS_OF_SERVICE`, `DRIVER_AGREEMENT`, `COOKIE_POLICY`, `REFUND_POLICY`.

كذلك `audienceFilter` و`roleAudiences` صحيحان: السائق يحصل على `ALL` + `DRIVER` معًا، فلا تفوته المستندات العامة. **لم يُمَس أي من ذلك.**

## 2. العطل الحقيقي الذي عُولج

المستندات مفصولة باللغة على مستوى الصف:

```prisma
@@unique([type, audience, locale])
```

أي أن الشروط بالعربية والفرنسية والإنجليزية **ثلاثة صفوف مستقلة**، ولا شيء في النظام يضمن أن اللوحة ترجمت كل مستند إلى اللغات الثلاث. ومع ذلك كان `publicList` يرشّح باللغة ترشيحًا صارمًا:

```ts
...(locale ? { locale: locale.trim().toLowerCase() } : {}),
```

ونتيجته أن **الحالتين الممكنتين لتطبيق بثلاث لغات كانتا معطوبتين**:

1. **مع `locale=fr`** واللوحة أضافت العربية وحدها → الترشيح يُرجع `[]`، وشاشة الشروط تظهر **فارغة تمامًا** مع أن المستند منشور وفعّال. سائق يختار الفرنسية من مدخل التطبيق لا يرى شروطًا إطلاقًا.
2. **بلا `locale`** واللوحة أضافت `ar` و`fr` و`en` → تُرجَع **ثلاث نسخ من نفس المستند**، والتطبيق لا يملك أي معيار لاختيار واحدة، فيعرض الشروط مكرّرة ثلاث مرات.

ولم يكن هناك خيار ثالث. والأسوأ أن `pendingForUser` لا يرشّح باللغة أصلًا، فلو ترجمت اللوحة الشروط إلى ثلاث لغات لطُولب السائق بالموافقة على **نفس المستند ثلاث مرات** قبل أن يدخل التطبيق. والموافقة حقها أن تكون واحدة لكل مستند، لا واحدة لكل ترجمة.

## 3. التعديلات (ملفان، بلا ترحيل)

**`src/modules/legal/legal.service.ts`**

- ثابت `LEGAL_FALLBACK_LOCALE = "ar"` — مطابق لـ `locale String @default("ar")` في `schema.prisma`، فلا رقم ولا لغة مخترعة.
- `publicList`: أُزيل الترشيح الصارم من استعلام قاعدة البيانات، وصار الاختيار في الذاكرة: صف واحد لكل `(type, audience)` بأفضلية **اللغة المطلوبة → العربية → أول متاح**.
- الرد أصبح يُعلن اللغة صراحةً: `requestedLocale` و`resolvedLocale` و`isFallbackLocale`، حتى يستطيع التطبيق تنبيه السائق أن النص معروض بلغة أخرى، فلا يظهر نص عربي داخل واجهة فرنسية بلا تفسير.
- `pendingForUser(actor, locale?)`: يستعمل نفس المنطق، فتصبح المطالبة بالموافقة **مرة واحدة لكل مستند**.
- مساعد خاص `pickOnePerDocument` — نقطة واحدة للمنطق، تستعملها الدالتان، فلا تكرار.

**`src/modules/legal/legal.controller.ts`**

- `GET /api/legal-documents/pending` يقبل `?locale=` اختياريًا ويمرّره إلى الخدمة. إضافة محضة: تركُه فارغًا يعمل كما كان مع أفضلية العربية.

لم يُمَس مسار اللوحة ولا `create` ولا `update` ولا `publish` ولا `listVersions` ولا `accept`.

## 4. قرارات مقصودة

**لم أضف حقول ترجمة إلى الجدول.** كان يمكن تحويل `title`/`body` إلى `Json` بثلاث لغات (كما `nameI18n` في `VehicleType`)، لكن ذلك ترحيل مدمّر لجدول قانوني فيه موافقات موثّقة وإصدارات منشورة مربوطة بـ `publishedBody`. التصميم القائم (صف لكل لغة) صحيح ويعمل، وينقصه الاحتياط فقط.

**لم أفرض على اللوحة ترجمة كل مستند.** إلزام اللوحة بثلاث ترجمات قبل النشر يمنع نشر أي تحديث قانوني عاجل، وهو قرار منتج لا قرار كود.

**العربية هي الاحتياط لأن `schema.prisma` يقولها**، لا لأنني اخترتها.

## 5. عقد المسار للتطبيق

```
GET /api/public/legal?audience=DRIVER&locale=fr      (عام، بلا توكن)
```

```json
[
  {
    "id": "...",
    "type": "TERMS_OF_SERVICE",
    "audience": "DRIVER",
    "locale": "ar",
    "requestedLocale": "fr",
    "resolvedLocale": "ar",
    "isFallbackLocale": true,
    "title": "...",
    "body": "...",
    "summary": null,
    "version": 3,
    "requiresAcceptance": true,
    "effectiveAt": "...",
    "publishedAt": "..."
  }
]
```

```
GET  /api/legal-documents/pending?locale=fr          (توكن)
POST /api/legal-documents/:id/accept                 (توكن)
```

ملاحظات للتطبيق:

- مرّر `locale` دائمًا من نظام i18n القائم، ولا تكتب أي نص قانوني داخل التطبيق.
- إذا كان `isFallbackLocale` صحيحًا، اعرض تنبيهًا مترجمًا («هذا النص متاح بالعربية فقط حاليًا») — والتنبيه نفسه من ملفات i18n لا نصًا ثابتًا.
- `body` نص طويل من اللوحة؛ اعرضه قابلًا للتمرير ولا تقتطعه.
- لا يوجد الآن أكثر من صف واحد لكل نوع، فلا حاجة لأي إزالة تكرار في التطبيق.

## 6. الاختبار — لم يُشغَّل

**لم يُشغَّل `npm run build` ولا `tsc` ولا `npx prisma generate`**: مجلد `node_modules` غير موجود في البيئة ولا شبكة، و`npx tsc` يفشل قبل الوصول إلى الكود بخطأ إعداد:

```
tsconfig.json(12,5): error TS5102: Option 'baseUrl' has been removed.
```

ما تحقّق فعلًا:

- `prettier` حلّل الملفين بنجاح؛ و`legal.service.ts` **نظيف تمامًا** بلا أي ملاحظة.
- التحذير الوحيد في `legal.controller.ts` واقع في `findAll` عند السطر 66 — **كود سابق لم أعدّله**، وأُثبت ذلك بفرق `prettier` سطرًا بسطر. ولم أشغّل `--write` لئلا أخلط ضجيج تنسيق بعمل المرحلة.
- تأكيد وجود الرموز: `LEGAL_FALLBACK_LOCALE`, `pickOnePerDocument`, `isFallbackLocale`, `Query("locale")`.

يجب تشغيل `npm run build` في بيئتك قبل الاعتماد على هذه المرحلة.
